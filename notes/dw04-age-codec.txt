Prediction

Written before codec code. tests/age/inventory.json assigns each published
case a class and records its immutable data digest and expected payload/prefix
hash. valid means complete decryption; invalid includes no-match/authentication/
truncation failures. unsupported identifies a vector for a deliberately absent
profile, not a successful parse or a skip counted as a measured primitive pass.
No published case is predicted out-of-budget; extra generated cap rows are.

1. Key text: key-text accepts only all-one-case BIP-173, age recipient or
age-secret-key- identity, canonical exactly 32 decoded bytes; presentation of
identities is wholly uppercase. Mixed case, Bech32m, wrong HRP, short/long data,
nonzero/excess conversion padding and checksum mutation refuse without echo.
Delegate all base64/Bech32 operations to std, never private copies.
2. Header: parser validates original raw bytes with exact version, LF, spaces,
VCHAR arguments and canonical unpadded standard base64. Each body has zero or
more 64-column lines plus a mandatory shorter last line (possibly empty).
Preserve the original transcript through the three '-' bytes, excluding the
following space and MAC. Unknown valid stanzas stay in the transcript and are
never executed. Validate every known X25519 stanza, even after a usable one:
exactly two arguments counting the type, 32-byte ephemeral share and 32-byte
body before any unwrap. Reject scrypt mixed with any other stanza.
3. Wrap: a fresh 16-byte file key per operation, a fresh 32-byte scalar for
every stanza/file, E=X25519_base(e), S=X25519(e,R) with zero abort. Derive
HKDF-SHA-256(E||R,S,"age-encryption.org/v1/X25519",32). Seal the 16-byte
file key with nonce twelve zero bytes and empty AAD. Every recipient wraps
the same key independently: OR recovery, never two-factor authentication.
4. Header authentication: derive HKDF-SHA-256(empty,F,"header",32) and
HMAC-SHA-256 over the exact preserved transcript. Strictly decode 32 MAC
bytes and use bytes.is_equal_fixed_work over the whole tag. The header-MAC
position matrix observes no plaintext from a failed header.
5. Payload: draw a fresh 16-byte nonce and derive
HKDF-SHA-256(nonce,F,"payload",32). Chunk size is 65536 plaintext bytes,
AEAD tag is always 16 bytes, AAD empty, nonce=11-byte big-endian counter
starting zero || final byte 0/1. Empty input emits exactly one empty final
chunk; a nonempty exact multiple ends with a full final chunk. One byte of
lookahead distinguishes finality; short reads never mean EOF.
6. Decrypt: buffer a whole ciphertext chunk/tag before authentication; expose
only a verified chunk. Require a valid final chunk followed immediately by
EOF. The vector judge hashes all emitted authenticated prefix even on error.
Development correction from seven red published prefix rows: a full chunk is
first tried with the nonfinal nonce, then with the final nonce if needed.
A verified full chunk reaches the internal sink even when the next read finds
missing finality or trailing bytes. For a verified full final chunk, release
precedes the EOF check, but no complete-stream success does. Encryption alone
uses one-byte final-input lookahead. No unauthenticated chunk is released.
Appended bytes, second files, altered/reordered/dropped/spliced chunks, missing
or empty noninitial final chunks fail. A sink spy checks zero bytes from a
failed chunk. No test driver reports archive/backup/restore success.
7. Lifetimes: per-chunk regions release temporary allocations, not erase
secrets. Lifetime and Linux RSS rows use two generated stream sizes, a small
parent and a hard memory cap. Trace key/plaintext/ciphertext copies on error.
Nonce-seam tests independently exercise carry across every counter byte and
overflow, without shrinking production widths or writing impossible volumes.

Bounds remain 1 MiB raw header, 64 stanzas/identity attempts, 4096 bytes per
argument line, signed-64 byte accounting and 256 MiB total process RSS. Bound
checks precede growth and KDF work. These are application admission limits,
not age maxima. A changed bound or observable error taxonomy needs approval.
Expected categories are malformed header/key text, unsupported profile/version,
wrong key, header authentication, payload authentication/truncation, budget,
I/O/interruption and entropy_unqualified; exact new API outcome names will be
frozen before their rows and implementation.

Logical manifest reader and inventory boundary

Forbidden

No command data verb is enabled. There is no source walker, production inventory
capacity, complete restricted-control/object-content verifier, restore engine
or new encryption/archive framing. The owning filesystem prerequisite is
separate; a path-only whole-directory substitute is not implemented. The
multi-pass authenticated logical-verification scheduler remains a follow-on.
No third-party backup, archiver or encryption implementation source was read.

Inputs verified

The reader follows spec/manifest-v1.md, with the independently reversible
schema clarification committed before frozen vectors. Before: combined
selection/exclusion phase and unspecified tie/reason/group/count details.
After: ordered phases/tuples, reason registry, LF-inclusive line and decoded
string bounds, Unicode Cc paths, explicit symlink bytes/NUL behavior,
path-named hardlink groups and repeated metadata, declared directory parents,
zeroed deleted/absent-birthtime fields, all-hole sparse files, duplicate object
refusal and namespace-versus-unique-object byte totals. See the specification
for each exact rule rather than treating the tests as normative definitions.

The compiler/runtime/std review set is unchanged. The live command import
graph is unchanged and the existing core check asserts it. The source-inventory
module has no I/O capability and always returns inventory_host_unqualified.
That is a new explicit internal prerequisite name, not a change to CLI taxonomy;
production inventory admission still has inventory_budget_unqualified.

Prediction

Strict schema-directed scanning preserves duplicate decoded keys and exact
integer spelling instead of losing them through a generic JSON DOM. Native
hostile bytes must fail before typed manifest relations can be returned.
Terminal EOF, checked offsets, type-specific fields and forward hardlinks are
validated without opening any target path. Object-content hashes, control
schemas, object-set completeness and sparse logical digests still need a
separate full verifier. Accepted manifest parsing is never contents_verified.

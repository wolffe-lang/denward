Age codec review packet

Status

This is an internal, test-only ordinary binary age v1 X25519 codec. It is not
independently reviewed, not backup-release authorization, and must not be used
for a real backup before a separate review. Every command data verb remains
refused. A locally green development subset is not a full qualification record.

Lifetimes and claim limits

Per-attempt and per-chunk regions release allocations, not secret erasure.
The creation draw buffer retains its file key, nonce and ephemeral scalar
bytes until the enclosing allocation lifetime ends. Individual stanza regions
release extra scalar/agreement/salt/wrapping-key copies. Header recovery copies
only selected file-key bytes into the outer list; temporary candidate/KDF/MAC
allocations end per attempt. A session retains parsed header/transcript, key,
payload key and counter. Each payload region holds only a bounded complete
chunk/tag, candidate plaintext and write slices; successful partial writes
release each slice in a nested region. Failure unwinds regions but cannot
recall authenticated bytes already accepted by the caller's internal sink.
In particular, a verified nonfinal chunk is released before later chunks are
seen. Missing final authentication fails the whole stream, never succeeds.
This matches the published vectors' expected authenticated prefixes; no
unauthenticated byte is released. A caller must not act on a prefix. Restore
is not implemented here: its future controller must complete archive preflight
before target mutation, use private partial inodes for individual file writes,
and publish them only after the required stream verification succeeds. That
is not permission for a plaintext archive/cache spool, which remains forbidden.
No descriptor is closed, no file synced/renamed, and no receipt published by
the codec. Private partial cleanup and interruption/publication authority
remain the future controller's responsibility. The controller MUST compare
returned encrypt plaintext count with the archive length it intended to send:
early source EOF can otherwise produce a complete authentic ciphertext of a
truncated archive. A stream-success count alone is not archive completeness.
The mutation grammar is an implementer-written model alongside the parser;
it detects implementation slips, not shared specification misreadings.

Stricter cases: a usable stanza followed by a low-order share, malformed
known argument list or 31-byte body is refused here even where reference age
stops at the first usable stanza. Native key text accepts all-lowercase
identities and all-uppercase recipients as Bech32 permits, while reference
age refuses those presentations. The test driver rejects CRLF identity files
that reference age accepts; normalize such a test input explicitly, never
silently repair a key. These are compatibility limits, not extra security
claims. The retained generic 90-character Bech32 bound affects no 62/74-byte
native key, and does not claim support for longer recipient profiles.

Limits are application admission, not universal age-format maxima. Files
from other age implementations with more than 64 stanzas, more than 64
identity-and-stanza pairs, argument lines over 4096 bytes including LF, or
headers over 1 MiB are refused here; the reference accepts such files.
`truncated` also reports bytes after a valid final chunk and an empty
noninitial final chunk. An oversized body line can be budget through the
stream reader but header through parse_header; these entry points do not
promise identical diagnostic priority. A 256 MiB
process memory measurement must include runtime overhead, allocator behavior
and parent/spawn context. The Linux witnesses use a stronger 256 MiB
address-space bound and report the small parent's self peak as a reference,
not a guaranteed lower bound on the child: the development record's measured
child peaks were lower. Cumulative child rusage is an upper-bound observation,
not an intrinsic exact peak; do not subtract the parent reference from it.

Both builds divide on secret-derived operands. Default builds on both targets
include X25519 fe_carry 40, fe_freeze 38, fe_tobytes 62, clamp 2 and ladder 4,
and Poly1305 absorb 19, poly1305 50 and push_tag_word 7. Release x86-64
extracts scalar bits with an 8-bit DIV in the X25519 ladder (none on arm64).
Bech32 identity decoding divides identity-derived values on both targets;
its alphabet lookup also exits early on secret characters in both builds.
See wolf-std#151. The prior release-division-free statement missed unsigned
DIV and was false. Instruction latency on the intended CPUs is unqualified;
no timing claim is made. The capture gate permits only exact pinned known
sites tied to that issue; its exception list becomes empty when the std fix
is pinned. Real-backup use remains blocked on that fix and review.
Shipped binaries are release builds. Neither source fixed work, generated
instruction counts nor vector agreement certifies constant time. Checked and
lupin budget refusals are unsupported, never measured primitive passes.

PAX creation still refuses entropy_unqualified before drawing; actual PAX
interoperability remains an open later requirement. Deterministic decrypt has
no entropy prerequisite. Provider failure after admission still traps under
the pinned OS-random contract; it is not caught or renamed unavailable, and
there is no fallback. Test-only source copies substitute the descriptor
import and/or the pinned std random module's platform/provider seam, record
provenance hashes, and retain the production codec body. Models exercise
partial progress, zero progress, terminal I/O and interrupted-operation I/O;
they do not measure actual kernel EINTR or signal delivery. The provider trap
model checks no stdout ciphertext; the PAX guard copy checks no source/sink
operation before refusal and successful deterministic published-file decrypt.
No seam or deterministic entropy is exposed by a production entry point.
Qualification still requires their final exact-head records, maximum-header
parser/HMAC memory (not inferred from 64 KiB chunk RSS), bounded mutation
coverage/seeds/minimized failures, the authentication plant and the separate
independent reading. Actual controller interruption cleanup is still future
integration work, not something these interface models implement.

No armor, scrypt derivation, SSH/plugin/PQ/hybrid recipients, custom cipher,
custom labels/AAD, altered tag widths, random chunk nonces, extra wrapper,
append/resume or rewrap-in-place is implemented. This does not supply archive
preflight, ciphertext-only durable publication, trusted independent receipts,
restore confinement, recovery-key retention or a recovery rehearsal.

No professional audit, formal proof, FIPS certification, universal constant
time, wiping, mlock, swap/dump exclusion, post-quantum protection, whole-system
encryption, compromised-kernel/endpoint resistance, backup-author
authentication or freshness/rollback protection is claimed. Anybody knowing
public recipients can encrypt a replacement. Two recipients provide OR
recovery, not two-factor authentication. Losing all identities loses recovery.
